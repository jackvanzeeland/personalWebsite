# Consolidate Static Assets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fold the homemade top-level `assets/` static folder into Vite's standard `public/` folder, so there is exactly one canonical place for runtime-served static files, and delete the now-redundant `vite-plugin-static-copy` wiring.

**Architecture:** `assets/images` → `public/images`, `assets/files` → `public/files`, `assets/fonts` → `public/fonts`. URL prefixes drop the `assets/` segment entirely (e.g. `/assets/images/x.png` → `/images/x.png`), matching the existing `public/data/timeline.json` → `/data/timeline.json` convention. `src/data/*.ts` (compile-time bundled data) is untouched — this plan only touches runtime static files. `dist/` is build output and is never hand-edited.

**Tech Stack:** Vite 6, TypeScript, sharp (build-time image optimizer), no test framework changes needed — this is a file-migration task, not new logic.

## Global Constraints

- No behavior change: every URL the browser requests today must resolve to the same bytes after migration (just at a new path).
- Run `npm run typecheck` (tsc --noEmit) after every task — catches any string path used in a typed context and any broken import.
- Run a `grep` sweep for leftover `assets/` references after every task that touches source files.
- `assets/images/opt/` and `src/generated/imageManifest.ts` are build-generated — never hand-edit their contents; regenerate via `npm run optimize:images` after the source script is updated.
- Confirmed dead (no references found anywhere in the repo): `assets/data/projects.json`, `assets/css/` (empty), `assets/js/` (empty), and inside `assets/images/`: `favicon.ico`, `icon-192.png`, `icon-512.png`, plus the duplicate copies of `apple-touch-icon.png`, `favicon-16.png`, `favicon-32.png` (the real ones already live in `public/` root and are what `index.html` actually links to). These are deleted, not moved.
